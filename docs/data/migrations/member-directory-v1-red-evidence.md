# Member directory v1 - RED matrix evidence consolidation (T093)

Cut-off: 2026-09-04. Scope: the `Required RED matrix for T093/T097` section of
`member-directory-v1.md`, with its bullets numbered `R01`..`R45` in reading order. This document
maps every requirement to the evidence that exists today and states whether the approved cut-off
satisfies it.

No production read, write, deployment or migration was performed to produce this document. Every
cited test runs against synthetic data in the local Emulator or against in-memory fakes.

## Method

- Numbering: `R01` is the first bullet after `T093 must capture these failures before implementation:`
  and `R45` the last one before the `T097 must capture` block. The `T097` bullets are out of scope
  here and keep their own matrix.
- Evidence is cited as `path::test name`. Counts come from the `verify:mvp` run of 2026-09-04
  (234 files / 1653 unit tests, 13 files / 91 Rules tests) plus the two Emulator suites that run
  outside the gate: `qa/integration/member-directory-concurrency.test.ts` and
  `qa/tests/member-directory-auth-emulator.spec.ts`.
- Verdicts:
  - `covered` - the requirement has direct evidence.
  - `partial` - part of the requirement is proven; the missing clause is named in the row.
  - `out-of-cut` - the requirement applies only to the legacy-to-canonical _migration_ path
    (bootstrap chunks, forward chunks, approvals and consumptions, compensation, post-cutover
    rollback, identity-reconcile-paged-v2, global legacy-read elimination). That path is not
    implemented at this cut-off; see [Architectural decision](#architectural-decision-of-the-cut-off).
  - `pending` - the requirement applies to the implemented path and has no evidence yet. No row
    carries this verdict; every gap found is either `partial` or `out-of-cut`.

## Architectural decision of the cut-off

T093 did not migrate the legacy `members` collection. It initializes an **empty canonical
directory** (`apps/functions/src/members/member-directory-empty-initializer.ts`, CLI confirmation
`T093-EMPTY-CANONICAL-INITIALIZE`) at `stateRevision` zero and then feeds it exclusively through
audited administrative writers: admin create/edit, adult profile linking, family and minor creation,
and the reviewed PDF import.

Consequences for the RED matrix:

- The state machine, the guard chain and the Rules boundary are implemented and proven for **every**
  phase tuple, including the migration phases, because `memberDirectoryStateSchema` and
  `qa/rules/member-directory-boundary.test.ts` are exhaustive over them.
- The **executors** for `bootstrap`, `forward`, `compensation`, `rollback-projection`,
  `rollback-readonly`, `canonical-recovery` and `identity-reconcile` do not exist. A repository-wide
  search finds no writer for `memberDirectoryMigrationChunks`, no approval-consumption path and no
  `identity-reconcile-paged-v2` implementation - only the contracts, the Rules denials and the index
  exemptions that keep those collections closed and unreachable.
- The restore and backup-v3 rehearsal path (`R38`-`R44`) **is** implemented and largely proven,
  because it is the disaster-recovery guarantee required before staging, not part of the migration.

## What closed before T094-T097

Every gap that applied to the implemented path was closed on 2026-09-04:

- **R09** - `qa/unit/canonical-directory-export-boundary.test.ts` (new, 4 tests): no export surface
  reaches the canonical directory, and the emitted CSV keeps its five columns with no participant or
  actor value.
- **R15** - the over-limit wave in `qa/integration/member-directory-concurrency.test.ts` now runs
  2,000 requests in one window and proves the rate document and audit ID set are unchanged.
- **R28** - `qa/integration/member-directory-concurrency.test.ts::serializes the administrative and
adult-profile writers over one control plane` (new): identity collision across writer kinds is
  impossible by construction, and the two writers serialize over the shared control plane.
- **R40** - `apps/functions/src/data/backup-v3-rehearsal.test.ts::never attests when content drifts,
a nested write lands or a document is removed between I2 and I4` (new).
- **R44** - a real defect, now fixed. `backup-v3-rehearsal.ts` derived the attestation ID from a MAC
  that included the target read time, so a retry past the commit derived a different ID and created a
  second attestation. Attested and verification state are now separate: the attested MAC binds what
  the target holds, the verification MAC binds the read time and is returned rather than persisted,
  and a committed attestation is discovered through its stable ID after every stable field and its
  MAC verify. Two new tests cover convergence and divergence.

Two rows moved verdict rather than closing, because their remaining clauses turned out to belong to
machinery that does not exist at this cut-off:

- **R22** moved to `out-of-cut`. Source handoff, revocation and post-deadline recovery are part of
  the approval machinery of R20/R21, which mints and consumes nothing today.
- **R27** stays `partial`, with the legacy rollback source reconstruction explicitly deferred with
  the rest of the migration path.
